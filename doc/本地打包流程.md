# fanwebcaddy 本地打包流程

将 fanwebcaddy 插件编译进 Caddy，生成可直接部署到服务器的完整可执行文件。

## 前提条件

- 已安装 Go 1.22+
- 本地已克隆 fanwebcaddy 仓库

## 第一步：安装 xcaddy

```powershell
go install github.com/caddyserver/xcaddy/cmd/xcaddy@latest
```

安装完成后验证：

```powershell
xcaddy version
```

## 第二步：编译

在 `fanwebcaddy` 项目根目录下执行：

```powershell
# 编译 Linux amd64 版本（用于服务器部署）
$env:GOOS="linux"; $env:GOARCH="amd64"; xcaddy build v2.8.4 --with github.com/HYERIC/fanwebcaddy=.
```

参数说明：

| 参数 | 说明 |
|------|------|
| `GOOS=linux` | 目标操作系统为 Linux |
| `GOARCH=amd64` | 目标架构为 x86_64（ARM 服务器改为 arm64） |
| `v2.8.4` | Caddy 版本，与 go.mod 中依赖版本保持一致 |
| `--with github.com/HYERIC/fanwebcaddy=.` | 使用当前本地目录的插件代码 |

编译完成后，当前目录下生成 `caddy` 可执行文件（约 30~50 MB）。

## 第三步：本地验证（可选）

> 由于编译目标是 Linux，Windows 下无法直接执行，可跳过此步。

```powershell
# 查看文件信息
dir .\caddy
```

## 第四步：上传到服务器

```powershell
scp .\caddy user@your-server:/usr/local/bin/caddy
```

## 第五步：服务器部署

```bash
# 赋予执行权限
chmod +x /usr/local/bin/caddy

# 验证版本和插件
caddy version
caddy list-modules | grep fanweb
# 预期输出：dns.providers.fanweb
```

## 第六步：创建 Caddyfile

```bash
sudo mkdir -p /etc/caddy
sudo nano /etc/caddy/Caddyfile
```

配置内容（替换为实际域名和 fanwebbaidu 服务地址）：

```caddyfile
*.example.com example.com {
    tls {
        dns fanweb https://fanweb.example.com
    }
}
```

## 第七步：启动 Caddy

```bash
# 验证配置语法
caddy validate --config /etc/caddy/Caddyfile

# 启动
caddy run --config /etc/caddy/Caddyfile
```

### 注册为 systemd 服务（开机自启）

```bash
sudo tee /etc/systemd/system/caddy.service > /dev/null <<EOF
[Unit]
Description=Caddy
After=network.target

[Service]
ExecStart=/usr/local/bin/caddy run --config /etc/caddy/Caddyfile
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now caddy
```

## 常见问题

**Q: 编译时出现 504 Gateway Timeout 警告？**  
A: 是 `sum.golang.org` 校验超时，不影响编译结果，等待编译完成即可。

**Q: 需要更新插件后重新打包？**  
A: 修改 `provider.go` 代码后，重新执行第二步编译命令即可生成新的 `caddy` 文件，再上传覆盖服务器上的旧文件并重启服务：
```bash
sudo systemctl restart caddy
```
