# fanwebcaddy 服务器部署操作说明

## 前提

- 本地已完成打包，生成 `caddy` 可执行文件（位于 `fanwebcaddy\` 根目录）
- 服务器系统：Linux（CentOS / Ubuntu 均适用）
- 服务器已开放 80、443 端口
- fanwebbaidu 服务已正常运行，记录其访问地址，例如 `https://fanweb.example.com`

---

## 第一步：上传 caddy 到服务器

```bash
scp D:\development\workspace\GoProjects\fanwebcaddy\caddy root@your-server-ip:/usr/local/bin/caddy
```

**预期结果：**
```
caddy                        100%   45MB   5.2MB/s   00:08
```

---

## 第二步：赋予执行权限

```bash
chmod +x /usr/local/bin/caddy
```

**预期结果：** 无报错输出。

---

## 第三步：验证 caddy 及插件

```bash
caddy version
```

**预期结果：**
```
v2.8.4 h1:xxxxxxxxxxxxxxxx
```

```bash
caddy list-modules | grep fanweb
```

**预期结果：**
```
dns.providers.fanweb
```

> 如果没有输出 `dns.providers.fanweb`，说明打包时插件未注入，需返回本地重新编译。

---

## 第四步：创建配置目录和 Caddyfile

### 4.1 创建目录

```bash
mkdir -p /etc/caddy
mkdir -p /var/log/caddy
```

### 4.2 创建 Caddyfile

文件路径固定为：**`/etc/caddy/Caddyfile`**（无扩展名）

```bash
nano /etc/caddy/Caddyfile
```

### 4.3 填写配置内容

将以下内容粘贴进去，替换 `example.com` 和 fanwebbaidu 地址：

```caddyfile
{
    email your@email.com
}

*.example.com example.com {
    tls {
        dns fanweb https://fanweb.example.com
    }
}
```

配置项说明：

| 配置项 | 说明 |
|--------|------|
| `email` | Let's Encrypt 注册邮箱，证书到期通知用 |
| `*.example.com` | 申请通配符证书覆盖所有子域名 |
| `example.com` | 同时覆盖根域名 |
| `dns fanweb` | 使用 fanweb DNS Provider 完成 DNS-01 验证 |
| `https://fanweb.example.com` | fanwebbaidu 服务地址 |

保存退出：`Ctrl+O` → `Enter` → `Ctrl+X`

---

## 第五步：验证配置语法

```bash
caddy validate --config /etc/caddy/Caddyfile
```

**预期结果：**
```
Valid configuration
```

> 如有报错，检查 Caddyfile 缩进和域名格式是否正确。

---

## 第六步：注册 systemd 服务

```bash
tee /etc/systemd/system/caddy.service > /dev/null <<EOF
[Unit]
Description=Caddy Web Server
Documentation=https://caddyserver.com/docs/
After=network.target network-online.target
Requires=network-online.target

[Service]
User=root
ExecStart=/usr/local/bin/caddy run --environ --config /etc/caddy/Caddyfile
ExecReload=/usr/local/bin/caddy reload --config /etc/caddy/Caddyfile --force
TimeoutStopSec=5s
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF
```

```bash
systemctl daemon-reload
systemctl enable caddy
```

**预期结果：**
```
Created symlink /etc/systemd/system/multi-user.target.wants/caddy.service → /etc/systemd/system/caddy.service.
```

---

## 第七步：启动服务

```bash
systemctl start caddy
```

查看启动状态：

```bash
systemctl status caddy
```

**预期结果：**
```
● caddy.service - Caddy Web Server
     Loaded: loaded (/etc/systemd/system/caddy.service; enabled)
     Active: active (running) since ...
```

---

## 第八步：查看证书申请日志

```bash
journalctl -u caddy -f
```

**预期关键日志（DNS-01 验证过程）：**
```
INFO    tls.obtain  obtaining certificate   {"domains": ["*.example.com", "example.com"]}
INFO    tls.obtain  waiting for solver      {"challenge": "dns-01"}
INFO    tls.obtain  certificate obtained    {"domains": ["*.example.com", "example.com"]}
```

> 首次申请证书约需 1~2 分钟，Let's Encrypt 需要验证 TXT 记录。

---

## 常用运维命令

```bash
# 重启服务
systemctl restart caddy

# 热重载配置（不中断连接）
caddy reload --config /etc/caddy/Caddyfile

# 查看实时日志
journalctl -u caddy -f

# 停止服务
systemctl stop caddy
```

## 5.3 Caddy 服务器升级

备份线上 Caddy 二进制和 Caddyfile：

```bash
cp /usr/local/bin/caddy /usr/local/bin/caddy.bak.$(date +%Y%m%d%H%M%S)
cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak.$(date +%Y%m%d%H%M%S)
```

上传本地打包的 caddy 到服务器，替换原二进制：

```bash
scp ./caddy root@server:/usr/local/bin/caddy.new
ssh root@server "mv /usr/local/bin/caddy.new /usr/local/bin/caddy && chmod +x /usr/local/bin/caddy"
```

更新 Caddyfile，加入 events 全局块（推荐方式 A）：

```caddyfile
events {
    on cert_obtained fanweb http://localhost:9100/api/v1/fan/fanCaddyOutside/certEvent
    on cert_failed fanweb http://localhost:9100/api/v1/fan/fanCaddyOutside/certEvent
}
```

校验配置并热重载：

```bash
caddy validate --config /etc/caddy/Caddyfile
caddy reload --config /etc/caddy/Caddyfile --force
```

如果 validate 失败，先回滚 Caddyfile，不要执行 reload。
如果 reload 后 Caddy 异常，立即回滚二进制：`mv /usr/local/bin/caddy.bak.* /usr/local/bin/caddy` 并重启。

## 5.4 验证

查看 Caddy 日志确认事件处理器已加载：`caddy list-modules | grep fanweb`。
触发一次证书申请（或等待自然续期），观察 fanwebbaidu 是否收到 `cert_obtained` 或 `cert_failed` 回调。
检查 `fan_caddy_cert_item.fail_reason` 是否被正确写入。

## 5.5 回滚方案

**fanwebbaidu 回滚**：直接回滚代码并重启。

**数据库回滚**：如需回滚，可执行 `ALTER TABLE fan_caddy_cert_item DROP COLUMN fail_reason;`（但通常保留该字段不影响旧版本）。

**Caddy 回滚**：替换为备份二进制，恢复备份 Caddyfile，执行 `caddy reload`。
